## Historia

**Como** agente **quiero** cambiar el estado de un caso **para** reflejar su avance.

## Reglas de negocio

1. La máquina de estados vive en un único módulo del backend, `services/estados.js`, que reutilizan HU-04, 06 y 07:

   ```
   Pendiente → En análisis → En atención → En validación → Cerrada
                                 ↑               │
                                 └── devolución ─┘
   ```

2. El endpoint genérico solo permite **avanzar un paso**:
   - `Pendiente → En análisis`
   - `En análisis → En atención`
   - `En atención → En validación`
3. **`Cerrada` y la devolución (`En validación → En atención`) quedan reservadas a la validación** (HU-07, `POST /api/casos/:id/validacion`), que exige rol validador y motivo. El endpoint genérico las rechaza.
4. Un caso `Cerrada` no puede cambiar.
5. Pasar al mismo estado en que ya está el caso es una transición inválida.
6. Quien cambia el estado es el usuario de prueba seleccionado. Debe existir, estar activo y tener rol `agente`.
7. El cambio de estado y su registro en `historial` (evento `cambio_estado`, estado anterior, estado nuevo, usuario, fecha y un `detalle` opcional) se hacen **en la misma transacción**. El caso se lee con `SELECT … FOR UPDATE` para que dos cambios simultáneos no se pisen.
8. **Se agrega en el Sprint 2:**
   - Para pasar a `En atención`, el caso debe tener un agente asignado (HU-04).
   - Para pasar a `En validación`, debe tener al menos una atención con solución (HU-06).

## Criterios de aceptación

- **E1 (CP-04):** *Given* un caso `Pendiente`, *When* el agente lo pasa a `En análisis`, *Then* el estado se actualiza y se crea un registro en el historial con el estado anterior y el nuevo.
- **E2 (CP-05):** *Given* un caso `Pendiente`, *When* intenta pasarlo directamente a `Cerrada` o a `En validación`, *Then* el sistema lo impide (`409`) y no cambia nada: ni el caso ni el historial.
- **E3:** *Given* un caso `Cerrada`, *When* intenta cambiar su estado, *Then* el sistema lo rechaza (`409`).
- **E4:** *Given* un caso `En validación`, *When* intenta devolverlo a `En atención` por este endpoint, *Then* el sistema lo rechaza (`409`) e indica que se hace por validación.
- **E5:** *Given* un caso en cualquier estado, *When* el agente abre la bandeja, *Then* solo ve los botones de las transiciones permitidas.

## Excepciones

| Situación | Respuesta |
|---|---|
| El caso no existe | `404` |
| `estado` falta o no es uno de los 5 valores | `400` |
| El usuario no existe, está inactivo o no es agente | `400` |
| Transición fuera del mapa, al mismo estado, a `Cerrada` o devolución | `409`, con las transiciones permitidas en `detalles` |
| El caso está `Cerrada` | `409` |
| Error de la base de datos | `500` y *rollback*: no cambian ni el caso ni el historial |

## Diseño

**API:** `PATCH /api/casos/:id/estado`

```json
{ "estado": "En análisis", "usuario_id": 3, "detalle": "Se revisa la configuración del AP." }
```

La respuesta `200` devuelve el caso actualizado.

Si la transición no está permitida, la respuesta es `409`:

```json
{ "error": "Transición no permitida: Pendiente → Cerrada", "detalles": ["Desde Pendiente solo se puede pasar a: En análisis"] }
```

**Pantalla:** en `/bandeja-soporte`, cada fila muestra un botón por cada transición permitida desde su estado. El frontend tiene una copia del mapa de transiciones solo para decidir qué botones mostrar; quien decide de verdad es el backend. Si el backend rechaza el cambio, se muestra su `error` y la fila se recarga.

## Decisiones del refinement

| # | Pregunta | Decisión |
|---|---|---|
| R1 | ¿El endpoint genérico permite la devolución? | **No.** La devolución exige motivo y rol validador, así que solo existe en HU-07. El mapa de `estados.js` la incluye, pero el endpoint genérico la rechaza. |
| R2 | ¿Dónde van los controles si no hay pantalla de detalle? | **En la bandeja** (ver HU-03, R2). |
| R3 | ¿Qué valor de `evento` se guarda? | `cambio_estado`, como en `seeds.sql` (D-08). |
| R4 | ¿Qué código se devuelve al cambiar al mismo estado? | `409`, porque es una transición fuera del mapa. |
