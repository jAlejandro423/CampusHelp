## Historia

**Como** solicitante **quiero** consultar mis casos **para** conocer su estado.

## Reglas de negocio

1. El solicitante solo ve los casos en los que `usuario_id` es él.
2. Cada caso muestra:
   - ID
   - título
   - tipo
   - área y categoría
   - prioridad
   - estado
   - fecha de creación
   - agente asignado, o "Sin asignar" si no tiene
3. El orden es por **fecha de creación descendente**, del más reciente al más antiguo.
4. Se muestran todos los estados, incluidos los casos `Cerrada`.
5. El estado que se muestra es siempre el actual, leído de MySQL en cada carga.

## Criterios de aceptación

- **E1:** *Given* un solicitante con 2 casos y otro usuario con 1, *When* abre "Mis casos", *Then* ve solo sus 2 casos con su estado actual.
- **E2:** *Given* un solicitante sin casos, *When* abre "Mis casos", *Then* ve un mensaje de lista vacía.
- **E3:** *Given* que un agente cambió el estado de uno de sus casos (HU-05), *When* recarga la vista, *Then* ve el estado actualizado.
- **E4:** *Given* varios casos, *When* abre "Mis casos", *Then* el más reciente aparece primero.

## Excepciones

| Situación | Respuesta |
|---|---|
| `usuario_id` no es un entero positivo | `400` |
| `usuario_id` válido, pero sin casos o inexistente | `200 []`: es un filtro, no un recurso (igual que D-06) |
| La API no responde | La vista muestra un mensaje de error, no una lista vacía |

## Diseño

**API:** `GET /api/casos?usuario_id=1`.

Es el mismo endpoint que usarán HU-03 (`bandeja=1`) y HU-09 (filtros), así que los filtros se combinan con `AND`. Cada elemento de la respuesta tiene esta forma:

```json
{
  "id": 1, "tipo": "Incidente", "titulo": "…", "prioridad": "P1", "estado": "Pendiente",
  "fecha_creacion": "2026-10-06T14:00:00.000Z",
  "area_id": 3, "area": "Red y conectividad",
  "categoria_id": 8, "categoria": "Wi-Fi",
  "usuario_id": 1, "solicitante": "Laura Gómez",
  "agente_id": null, "agente": null
}
```

**Pantalla:** `/mis-solicitudes` (`MisSolicitudes.tsx`), en el menú del solicitante con el nombre "Mis Casos".
- Tabla con badge de color por estado.
- Estado vacío.
- Usa el `usuario.id` de `useUsuario()` y recarga al cambiar de usuario.

## Decisiones del refinement

| # | Pregunta | Decisión |

| R1 | ¿Endpoint propio o filtro sobre `GET /api/casos`? | **Filtro.** Un solo endpoint con query params para HU-02, 03 y 09 (#26 y #29). |
