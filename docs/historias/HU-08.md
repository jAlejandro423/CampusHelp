## Historia

**Como** usuario **quiero** ver el historial de un caso **para** saber qué pasó, quién lo hizo y cuándo.

## Reglas de negocio

1. El historial es de solo lectura y se ordena por fecha y luego por `id`, del más antiguo al más reciente.
2. Cada registro muestra evento, estado anterior, estado nuevo, nombre del usuario, fecha y `detalle` (por ejemplo, el motivo de una devolución).
3. El **solicitante solo ve el historial de sus casos** (RN-05). Agente, validador y administrador ven el de cualquier caso.
4. Quien consulta envía su `usuario_id`; debe existir y estar activo.
5. Los eventos son los del catálogo: `creacion`, `asignacion`, `cambio_estado`, `atencion`, `envio_validacion`, `devolucion` y `cierre` (D-08 y [D-15](../decisiones.md)).

## Criterios de aceptación

- **E1:** *Given* un caso que recorrió el flujo completo, *When* se consulta su historial, *Then* aparecen en orden la creación, la asignación, los cambios de estado, la atención, el envío a validación y el cierre, cada uno con usuario y fecha.
- **E2:** *Given* un caso devuelto, *When* se consulta su historial, *Then* aparece la devolución con su motivo.
- **E3:** *Given* un solicitante, *When* pide el historial de un caso ajeno, *Then* el sistema responde `404` y no muestra nada.
- **E4:** *Given* Mis Solicitudes, la Bandeja o Por validar, *When* el usuario pulsa "Ver historial", *Then* ve la línea de tiempo del caso.

## Excepciones

| Situación | Respuesta |
|---|---|
| El caso no existe | `404` |
| El solicitante pide un caso que no es suyo | `404` (no se revela si existe) |
| `id` o `usuario_id` no son enteros positivos | `400` |
| El usuario no existe o está inactivo | `400` |
| Error de la base de datos | `500` |

## Diseño

**API:** `GET /api/casos/:id/historial?usuario_id=1` → `200`

```json
[
  {
    "id": 1, "caso_id": 1, "evento": "creacion",
    "estado_anterior": null, "estado_nuevo": "Pendiente",
    "usuario_id": 1, "usuario": "Laura Gómez",
    "fecha": "2026-10-06T09:00:00", "detalle": "Caso registrado por la solicitante."
  }
]
```

**Pantalla:** componente reutilizable de **línea de tiempo** (en un modal o un panel desplegable) con un botón **Ver historial** en las filas de `/mis-solicitudes`, `/bandeja-soporte` y `/por-validar`. Cada evento muestra un texto legible ("Asignado a…", "Devuelto: motivo…"), el cambio de estado con los badges existentes, el usuario y la fecha.
